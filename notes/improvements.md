# Улучшения функционала — план

Дорожная карта доработок, приоритизирована по ценности для отеля. Составлена по аудиту кодовой базы 2026-08-12.

## Приоритет 1 — деньги

### 1. Оплаты по брони
- **Проблема:** в приложении нет учёта реальных оплат. Выручка дашборда = `sum(total_price)` по `checked_out` — это выручка *по тарифу*, а не принятые деньги.
- **Решение:** модель `Payment` (booking, amount, method: cash/card/transfer, at, note). Предоплата при подтверждении, доплата/расчёт при выезде, баланс `paid/due`. Блок в карточке брони, колонка в списке, учёт реальных оплат в дашборде, поле в CSV-экспорте.
- **Затрагивает:** новая модель+миграция, admin bookings show/index, дашборд, `bookings_csv_exporter.rb`.
- **Статус:** ✅ реализовано (426 тестов, rubocop 0)

### 2. Снимок цены при бронировании
- **Проблема:** `BookingPricing#calculate_total_price` (`app/models/concerns/booking_pricing.rb`) пересчитывает цену при каждой смене дат/номера **по текущим** `PricePeriod`. Изменение сезонного коэффициента задним числом молча меняет цену существующей брони.
- **Решение:** замораживать ночную раскладку (`NightlyEntry`, `app/services/nightly_pricing.rb`) в отдельную таблицу/JSON при подтверждении; в карточке показывать «цена зафиксирована по тарифу на дату X».
- **Статус:** ✅ реализовано: снимок пишется при каждом пересчёте цены (создание/смена дат/номера), а не только при подтверждении — расчёт и заморозка атомарны в `BookingPricing`, отдельных ночей не бывает в другой раскладке.

### 3. Closed dates / min stay в тарифах
- **Проблема:** `PricePeriod` имеет только `multiplier`.
- **Решение:** добавить `min_nights`, `closed_on`/запрет заезда и выбытия в даты; валидация в `BookingCreator`, блокировка выбора в публичной форме.
- **Статус:** ✅ реализовано: `PricePeriod#min_nights` + модель `ClosedDate` (глобальные закрытые ночи, CRUD `/admin/closed_dates`); `StayRules` (min_nights между датами, закрытые ночи) подключён в `RoomAvailability` (виджет: Failure с текстом → 422) и `BookingCreator` (публичная форма); админ бронирует вручную поверх ограничений (457 тестов, rubocop 0).

## Приоритет 2 — гости (CRM)

### 4. Карточка гостя и слияние дублей
- **Проблема:** `Guest.find_or_initialize_by(email)` плодит дубли при разном паспорте/телефоне.
- **Решение:** карточка гостя (история броней, доход от гостя, предпочтения/аллергии/VIP, комментарии) + слияние дублей по email/паспорту/телефону.
- **Статус:** ✅ реализовано: `is_vip`/`preferences` у гостя, карточка `/admin/guests/:id` (история броней, сумма за всё время, завершённые заезды, VIP-бейдж, дубли), слияние «Объединить с этим гостем» — `possible_duplicates` (email без учёта регистра, телефон, паспорт) + `merge_into!` переносит брони и объединяет профиль; колонки VIP/Предпочтения в CSV (470 тестов, rubocop 0).

### 5. Политика персональных данных (152-ФЗ)
- **Проблема:** храним паспортные данные без учёта согласий.
- **Решение:** счётчик согласий, чекбокс соглашения в публичной форме брони.
- **Статус:** ✅ реализовано: `ConsentLog` (guest_id, signed_at) — запись при каждой публичной брони (счётчик согласий на карточке гостя), обязательный чекбокс в публичной форме брони (без него BookingCreator возвращает ошибку), страница `/privacy` с политикой ПДн + ссылка в футере (478 тестов, rubocop 0).

## Приоритет 3 — операционка

### 6. Админ-уведомления о новых бронях
- **Проблема:** `app/models/notification.rb` шлёт только пользователю; админ узнаёт о новой броне, лишь открыв дашборд.
- **Решение:** канал «для админа» (колокол в topbar + email).
- **Статус:** ✅ реализовано: `Notification#to_admin` (user_id необязателен, письма — только пользователям), при создании брони (кроме созданной самим админом — `Thread.current[:current_administrator]`) и нового отзыва — уведомление в приложении; колокол «Уведомления» с бейджем непрочитанных в topbar, список с «Открыть»/«Прочитать»/«Прочитать все» (483 теста, rubocop 0).

### 7. Статусы/история уборки номеров
- **Проблема:** журнала смены `room.status` нет (в отличие от `BookingAuditLog`).
- **Решение:** журнал смены статуса, авто-`cleaning` после `check_out` (связь с `RoomStatusSync`), кнопка «Уборка завершена» → `available`.
- **Статус:** ✅ реализовано: `RoomStatusLog` пишет каждую смену статуса (ручную — из `Room#after_update`, автоматическую в `RoomStatusSync` — явно, т.к. тот использует `update_column`); выезд → `cleaning` (отмена → `available`), кнопка «Уборка завершена» в списке, страница «История статусов» `/admin/rooms/:id/status_history` (489 тестов, rubocop 0).

### 8. Отчёты за период
- **Проблема:** экспортируются только bookings/guests.
- **Решение:** отчёт «выручка факт/план», загрузка по категориям номеров, ночная загрузка; экспорт в CSV; кнопка на дашборде.
- **Статус:** ✅ реализовано: `Reports::PeriodReport` (план по ночам из снимка цен, факт из оплат, занятость, по категориям, итоги; ограничение периода 92 дня), `/admin/reports` + экспорт CSV (`ReportsCsvExporter`), кнопка «Отчёт за текущий месяц» на дашборде, пункт «Отчёты» в sidebar (499 тестов, rubocop 0).

## Приоритет 4 — UX

### 9. No-show политика
- **Проблема:** sweeper (`app/jobs/booking_sweeper_job.rb`) отменяет no-show, но предупреждения/штрафа нет.
- **Решение:** напоминание за 24 ч + штраф (связь с депозитом из п.1).
- **Статус:** ✅ реализовано: напоминание за сутки уже было (`send_check_in_reminders` → `BookingMailer.check_in_reminder`, только confirmed с `user`), добавлен штраф за неявку — `bookings.no_show_fee` = цена первой ночи (из снимка, фолбэк `total_price / ночей`), начисляется sweeper'ом при автоматической отмене no-show (идемпотентно) и входит в «Долг» (`due_amount` включает штраф): карточка брони, список, CSV «Долг, ₽» (502 теста, rubocop 0).

### 10. Публичный виджет доступности
- **Проблема:** публичная форма не показывает стоимость до отправки.
- **Решение:** расчёт итога за выбранные даты (данные уже есть — `available_rooms`, `NightlyPricing`).

### 11. Поиск по каталогу номеров
- **Решение:** фильтры по количеству гостей и услугам на странице номеров (`Room#available_on`, amenity-связи уже есть).

## Предлагаемый старт

Начать с **п.1 + п.2** (оплаты + снимок цены) — самый заметный пробел, либо собранный мини-спринт из нескольких пунктов. Решение по выбору зафиксировать в [[decisions|decisions.md]].

**Статус:** п.1–п.9 реализованы (ADR «Оплаты по брони и снимок цены», «Закрытые даты», «Карточка гостя и слияние дублей», «Согласие на обработку ПДн», «Админ-уведомления», «Журнал статусов номеров», «Отчёты за период», «Штраф за неявку»). Следующий кандидат: **п.10** (публичный виджет доступности — показ стоимости до брони).
